Medical Image Segmentation & Detection

Two 3D medical-imaging pipelines for cardiac CT, built for the AI CUP 2025 competition: UNet3D whole-heart segmentation and YOLOv12 aortic-valve detection.

Overview

This was my first machine learning project and my first real exposure to computer vision — an end-to-end pipeline from raw CT volumes to a trained model to a leaderboard submission, done solo (data preprocessing, manual annotation in 3D Slicer and LabelMe, training, tuning, and inference all mine). Coming from a vehicle-engineering background, it was also a chance to apply deep learning to a domain outside vehicles — one that turned out to share real structure with autonomous-vehicle perception. Both tasks here work on volumetric (3D) data and need to find small, low-contrast targets reliably: the same underlying problem as lidar/voxel processing and small-object detection in ADAS. This project is what first pulled me toward autonomous driving as a direction.

The pipeline splits into two independent tracks, both built on the same cardiac CT patient cohort (50 labeled training cases, 50 held-out test cases): a UNet3D network that segments the whole heart from cardiac CT volumes, and a YOLOv12 detector tuned to localize the aortic valve — a small, low-contrast target that's easy to miss.

Track I — Myocardial Segmentation

A MONAI UNet3D (channels 64→128→256→256, stride-2 downsampling) trained with DiceCELoss + AdamW. Preprocessing clips intensities to [-42, 423] HU, resamples to 0.7×0.7×1.0 mm spacing, and extracts 128×128×128 ROI patches. Reached 0.7439 Dice on the public leaderboard.

  • Next up: a hybrid loss (Dice + Focal + a boundary term) to sharpen edges, model ensembling, semi-supervised/transfer learning to use unlabeled scans, and morphological post-processing to clean up spurious small regions.

Track II — Aortic Valve Detection

YOLOv12 (Ultralytics), fine-tuned from yolo12n.pt on 2,168 labeled training slices / 619 validation slices, trained in stages (resume=True) around Colab's daily compute limits. Reached 0.9396 Dice on the public leaderboard with inference at conf=0.05, iou=0.65.

What I actually tried during the competition, not a hypothetical list:

  • Compared batch=8 and batch=16 training runs at 50 epochs before settling on batch=4 as the best-performing configuration.
  • Tried swapping the yolo12n.pt base checkpoint for an earlier fine-tuned best.pt and continuing training from there.
  • Tuned inference-time conf/iou thresholds repeatedly against a hard constraint — only 3 submissions/day — so each iteration had to be planned carefully.
  • Next up: higher input resolution, a finer conf/IoU sweep, and a larger YOLO backbone.

Every result image above comes from reloading the actual trained checkpoints (best.pt for detection, the UNet3D checkpoint for segmentation) and running real inference on held-out test CT scans — not screenshots from the competition report.
